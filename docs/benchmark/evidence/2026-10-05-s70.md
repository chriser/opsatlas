# REF S70 #2206: the test suite never reaches a live service; emergency recovery kept for the host's command (5 October 2026)

Two follow-ups recorded on REF F11 #2170, neither needing a decision. Tests only: no production code changes.

## Why

- **Live services.** The independent review of Bugs #2191 and #2192 found tests reaching for the local model server at
  `127.0.0.1:11434`; they pass when refused. Nothing in the suite stopped a test reaching a live service on this Mac:
  only the Sales workspace builder refused the network. Every gate run, and every reviewer's, should leave the live
  services alone.
- **Emergency recovery.** S68's IR2: `Identity.emergency_recovery` has no actor and no permission check, and no check
  limited its callers.

## Measured before the change

The full suite ran on main (`1beda5c`) with a temporary hook that refused the live ports and logged every attempt, and
logged any connection off this machine:

- 1,583 passed plus 8 expected failures, the same as without the hook. No test depends on a live service.
- 13 connections to the model server (`11434`), from 12 tests in 10 files (Tibi, the Tibi gateway, owned work). One
  comes from a background worker thread, so which test it lands under varies from run to run. Without the hook these
  reach the live server on every gate run.
- 1 connection to the diagram service (`5300`), from `tests/test_process_diagram_service_control.py`.
- No connection to any address off this machine.

## Red team, round 1 (`84e0d7e`): not ready

1 Medium and 6 Lows; nothing reached a live service in its runs. The report is local:
`research_notes/red-team-2026-10-05-s70.md`, with probes in `research_notes/red-team-s70-probes/`.

- **M1, fixed:** the guard saw only Python's socket methods, and uvloop connects from its own C code. uvicorn uses
  uvloop by default, and one test already runs uvicorn in a thread. uvloop is now blocked in the test process, so every
  event loop is asyncio's, whose connections go through the guard. A test proves an asyncio connection is refused.
- **L1, fixed:** a loopback port not on the list was reachable, so a proxy in the environment, or an unlisted local
  service, could carry a test's request onward. The rule is now stricter: a test connects only to loopback ports this
  test process opened itself (it records every port it binds), and never to a live service's port. The red team ran
  the whole suite under that rule; it passes.
- **L2, stated:** multiprocessing children, UDP datagrams, and the C socket class used directly are outside the guard,
  below. A port given as an object with `__index__` is now read as a number.
- **L3, fixed:** an autouse fixture checks after every test that the guard is still installed. If not, it puts it back
  and fails that test.
- **L4, fixed:**
  - the list test pins all eight ports;
  - the refusal tests stand in for the network, so a guard that stayed installed but stopped refusing would fail them
    instead of connecting;
  - the guard now has two proofs: the refusal switched off with the guard installed, and the guard uninstalled.
- **L5, fixed in part:**
  - the caller rule now counts a wrapper inside IAM's service, and a string that ends with `.emergency_recovery`;
  - it reports a defining module that no longer defines the method;
  - a new rule fails if any production module imports the host's command;
  - the rest is stated below.
- **One more fix, found by the new per-test check:** the leak sweep swapped in its own refusing `connect` for a whole
  module. It now relies on the suite's guard, which does the same job.
- **L6, records:** corrected on this page (the file count, the worker thread, the guard proofs counted apart,
  `connect_ex`, the diagram service manager).

## What changed

- **`tests/live_guard.py`:**
  - the live ports, read from `assistant.settings` where it names them;
  - `refused(address)`, the reason a connection is refused;
  - `install()`: the check in front of the socket class's `connect` and `connect_ex`, a record of every port the process
    binds, and uvloop blocked;
  - `installed()`, and `uninstall()` for the guard's proof only.
- **`tests/conftest.py`:**
  - installs the guard after the throwaway data folder is set, and before a guard is switched off, so the guard's own
    proofs can switch it off;
  - checks after every test that it is still installed.
- **`tests/test_live_guard.py`:**
  - each live port, through `127.0.0.1`, `localhost` and `::1`, is refused at once by `connect` and `connect_ex`;
  - an address off the machine is refused, and so is a loopback port the test did not open;
  - an asyncio connection is refused;
  - uvloop cannot be imported;
  - a port the test opened is reachable;
  - the list is exactly the eight ports.

  Each test first checks that the guard is installed. The refusal tests also stand in for the network.
- **`tests/boundary_rules.py`:** `SOLE_CALLERS` and `ENTRY_POINTS` (P3).
- **`tests/test_boundaries.py`:** both rules against the code, and against planted code.
- **`tests/guard_register.py`:** four guards, each proven:
  - the caller rule;
  - the entry-point rule;
  - the refusal, switched off with the guard installed;
  - the guard, uninstalled.
- **`docs/ways-of-working/Boundaries.md`:** the caller rule and the entry-point rule.

## The #2191 test and the diagram service

The review asked to stub the diagram client in #2191's in-audience test. That test runs in the Sales workspace builder,
which already refuses the network, and the guard now refuses the diagram port in every test. It passes with the service
refused, so it never depends on it.

## The failure list

Tests only.

- **A crash, a restart, a failed write, two requests at once, the evidence changing, date and time, model output:** not
  involved. No state is written; the guard is a function in front of a socket call.
- **Duplicate or malformed input:** an address that is not a host and port (a local socket) goes ahead unchanged. A
  port that is not a number is refused.
- **A dependency down or slow:** that is what the guard makes every live service look like, at once rather than after a
  timeout. `connect_ex` raises rather than returning an error code, so a refusal is never silent.
- **The diagram service manager:** under the guard, a manager that checks the service sees it as down. Its real
  start would launch a diagram service on port 5300. Its one test stubs both the check and the start, and no other test
  reaches it.

## Stated limits

- **A subprocess or a multiprocessing child** starts without the guard. Today five test files start a subprocess:
  - the guard proofs: pytest itself, under the same conftest, so guarded;
  - ruff, in the boundary tests;
  - `git grep`, in the role catalogue's test;
  - `git`, and the worktree set-up script, in its own test;
  - a short Python check of the ontology's alias order.

  None of them connects anywhere. Nothing uses multiprocessing.
- **UDP datagrams** (`sendto`) and the C socket class used directly (`_socket.socket`, `socket.SocketType`) are not
  checked. Nothing in the tests uses them.
- **Name lookups** are not blocked, only connections.
- **A port the process opened stays allowed** after its socket closes. The live services keep fixed ports, which are
  never allowed.
- **Another loopback address** (`127.0.0.2`, `0.0.0.0`) counts as off the machine and is refused, which is stricter
  than needed.
- **The caller rule reads names, not reachability.** It misses:
  - a method name built at run time (`getattr(iam, "emergency_" + "recovery")`), as computed names escape the other
    rules;
  - a `match` class pattern's keyword;
  - the tooling (`scripts/`, `evaluation/`), outside the rules by design (the Human's question on the tooling's scope).
