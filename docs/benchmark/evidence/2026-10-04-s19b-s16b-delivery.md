# REF S19b #2137 and S16b #2136: the delivery check, on every channel (design, 4 October 2026)

Claude's red team on REF H3b found both items on 3 October 2026. The Human decided S19b on 4 October 2026: approval is
checked in the delivery recheck, on every answer and every channel. S16b gives the avatar route the checks `/api/ask`
has. They share one mechanism, the last check before an answer is given, so they share one design, one branch and one
review. Tier: full (access, governance).

## Today

- **`/api/ask`** (`src/assistant/api/routes_ask.py`) checks twice after the answer is prepared:
  - **S16:** the asker may still ask (`still_allowed(request, "knowledge.ask")`).
  - **S19:** `EvidenceBundle.recheck` (`src/assistant/evidence/contract.py`) checks that every cited source is still
    readable by the asker (`visible`) and still the version it was. It does not check that the source is still
    approved. Worse, a source **deleted** while the answer was prepared passes: its current version is `None`, which
    the check treats as unknown.
- **`/api/avatar/answer`** (`src/assistant/api/routes_avatar.py`) prepares the answer, then makes a second model call
  to render it, and returns. It has neither check, and its window is a full model call longer.
- **Tibi's channels** (voice, the digital SME) compose answers from the Sales API. Before speaking, Tibi checks the
  answer digest again (`/api/sales/digest`). The digest covers the enabled records and the evidence versions they were
  enabled against (`services/opsatlas_sales/knowledge.py` `digest`, `eligible`).

## Promises

- **D1, approval at delivery (S19b).** An answer is given only if, at delivery, every document it cites meets all
  three conditions:
  - still **approved** (new);
  - still readable by the asker (S13, S16);
  - still the version it was (S19).

  Otherwise it is refused with today's 409, "The evidence changed while the answer was prepared; ask again." A
  document deleted while the answer was prepared is not approved, so the deletion gap closes too.
- **D2, every channel.**
  - The written channel (`/api/ask`) and the avatar channel (`/api/avatar/answer`) deliver through one function that
    makes both checks (S16 and the recheck).
  - Tibi's channels keep their check, the digest before speech. S19b proves with a test that withdrawing a cited
    document's approval changes the digest, so Tibi re-fetches and does not say it. If it does not, the digest takes
    the documents' approval.
- **D3, the avatar route (S16b).** It makes both checks after its rendering call, the last moment before delivery:
  - access revoked: 403, as `/api/ask`;
  - the evidence changed: 409, as `/api/ask`.
- **D4, one place.** One delivery function holds the checks. An inventory test proves that every production route that
  calls the answer service delivers through it.
- **D5, nothing else changes.**
  - An answer whose evidence is unchanged is delivered as today, with the same body and the same usage id.
  - The recheck's readability and version checks are unchanged.
  - The evaluation runners, which are not channels, are unchanged.

## Design

- **`EvidenceBundle.recheck`** takes a third check, `approved(item)`. Every item that rests on a document must have
  that document approved now.
- **What an item rests on depends on its citation's type.** A citation's `source_id` is not always a document. Checked
  on 4 October:
  - **`document`** (a retrieved passage): its `source_id` is the document's id. It is checked.
  - **`process_registry`** (a process record): its `source_id` is the process's id. It rests on the process record's
    `source_id`, a document, and that document is checked.
  - **`ontology_object`** (a fact): its `source_id` is the object's id. It rests on the document the object's
    `source_ref` names when that ref names a process or a source (`process_registry:<id>`, `compliance_latest:<id>`).
    Where the ref names no document in the register, the fact is given as today. This is stated.
  - **Governed sentences and other items without a document** are unaffected.
- **The answer service gets `rests_on(citation) -> list[document id]` and `approved_of(source_id) -> bool`,** wired by
  `create_app` next to `version_of`. They read the register, the process registry and the ontology store that the
  service answers from. A document is approved if its record exists and its approval is `approved`, so a deleted
  document is not. An item is approved when every document it rests on is approved. `deliver` builds the check from
  the result's citations, which keep their type, and hands it to `recheck`.
- **`assistant/api/delivery.py`** (new, in the `api` package, so no new import edge: `answer` never imports `api`)
  holds `deliver(request, answer_service, question, result)`. In order:
  1. S16's `still_allowed`, when the request has an actor.
  2. The bundle.
  3. `recheck(may_read, version_of, approved)`.
  4. 403 or 409 as today.

  `/api/ask` and `/api/avatar/answer` call it, the avatar route after rendering.
- **Tibi:** a test drives the Sales API. It enables a record, takes the digest, withdraws a cited document's approval,
  and requires the digest to change. If the test fails, `answer_digest` adds each enabled record's evidence approval.

## The failure list

- **The evidence changing underneath** is the point of the item:
  - approval withdrawn mid-answer;
  - a new version published mid-answer (S19, kept);
  - the document deleted mid-answer;
  - the document restricted mid-answer (S13, kept);
  - a fact's document withdrawn mid-answer.

  Each is a named test, through each channel.
- **Access changing mid-way:** a session revoked, or a role removed, while the answer or the avatar's rendering is
  prepared: 403 (S16, both routes).
- **Two requests at once:** an ask runs while a withdrawal commits. The ask takes no lock (reads never wait, S7), and
  the recheck reads the approval at delivery.
- **A dependency down or slow:** the avatar's rendering call failing or slow changes nothing about the checks; they run
  after it.
- **Duplicate or stale input, a crash, a restart:** delivery writes nothing, so there is nothing to leave half-done. The
  usage log entry is today's.
- **Date and time, and model output:** not involved. The tests use a fake generator that changes the evidence during
  generation.
- **A write that fails:** none; delivery only reads.

## Tests

- **Named tests per channel.** Approval withdrawn, a new version, deletion, a restriction, and a fact's document
  withdrawn, during generation (through a fake generator's hook): 409. Access revoked during generation or rendering:
  403. Unchanged evidence: delivered, with the body unchanged.
- **The inventory test:** every route calling the answer service delivers through `deliver`, found by an AST scan of
  the routes.
- **Tibi:** the digest changes when a cited document's approval is withdrawn.
- **A seeded random-scenario suite.** It mixes withdrawals, new versions, deletions, restrictions and revocations at
  random points during generation, over both channels. After every answer it checks that nothing withdrawn, deleted,
  changed or unreadable was given.
- **Guards:**
  - the approval check in `recheck`;
  - the deletion closing;
  - the avatar route's delivery.

## Stated limits

- **The check is the last moment, not a lock.** A withdrawal committed after the recheck, while the response is
  already being sent, is not seen by that answer. That is the same as S19 today.
- **A fact whose origin names no document in the register** (an external or compliance source with no register
  record) is given as today.
- **Answers already given are not recalled.**
