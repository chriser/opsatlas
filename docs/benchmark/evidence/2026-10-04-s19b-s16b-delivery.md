# REF S19b #2137 and S16b #2136: the delivery check, on every channel (design v2, 4 October 2026)

Claude's red team on REF H3b found both items on 3 October 2026. The Human decided S19b on 4 October 2026: approval is
checked in the delivery recheck, on every answer and every channel. S16b gives the avatar route the checks `/api/ask`
has. They share one mechanism, the last check before an answer is given, so they share one design, one branch and one
review. Tier: full (access, governance).

**Status: the stop rule applied after design round 2 (4 October 2026, night). The decision is parked for the Human.**
Nothing is built.

- **What round 2 found.** 1 High, 2 Mediums and 4 Lows on v2, in round 1's areas. The report is local,
  `research_notes/design-red-team-2026-10-04-s19b-s16b-round2.md`.
- **The flaw.** Delivery re-establishes three things by three means, each reading state that does not match the
  evidence:
  - readability, from the request's visibility, worked out when the answer began (a live gap today, Bug #2197);
  - a fact's approval, from a shared object's "last writer" `source_ref`, not the document the cited text came from;
  - an inventory that calls every route, which proves nothing for routes that need a body.
- **The red team's simpler shape**, the recommended option in `reports/Morning questions 2026-10-05.md`:
  - every item's documents are fixed when the evidence is built;
  - at delivery, each document is checked afresh: approved, readable through a new visibility, and for passages the
    same version;
  - facts rest on every document of the answer's reading;
  - a fixed list of allowed callers, with a planted self-test.

v2 below is kept as the record.

**v1, at `84749c4`.** Its design red team found 1 High, 7 Mediums and 4 Lows. The report is local:
`research_notes/design-red-team-2026-10-04-s19b-s16b.md`, with probes in `research_notes/design-red-team-s19b-probes/`.

- **What held.** The document part: the deletion gap is real, counting "no record" as "not approved" refuses nothing
  that should be given, Tibi's digest already changes, and `deliver` in `api` adds no cycle edge.
- **The High (DS1).** v1 resolved a fact to its document at delivery, from the facts map. But the withdrawal it checks
  for rebuilds the facts map first, so the fact's object is gone and the answer would be given. Reading state that
  changes mid-answer is the kind of fault H3b hit three times.
- **The fix, H3b's own shape.** Record what each item rests on when the evidence is built. At delivery, read only the
  register.

## Today

- **`/api/ask`** checks twice after the answer is prepared:
  - **S16:** the asker may still ask.
  - **S19:** every cited source is still readable and still the version it was.

  It does not check approval. A source deleted mid-answer passes, because its current version is `None`, which the
  check treats as unknown.
- **`/api/avatar/answer`** has neither check, and its window is a model call longer. It needs both `avatar.use` and
  `knowledge.ask`.
- **Tibi's channels** check the answer digest again before speaking. The digest already changes when a cited
  document is withdrawn, deleted or restricted (the red team's probes).
  - The voice channel checks once, before a reply's first sentence, while the rest is still being generated.
  - The text channel checks after the whole reply.

## Promises (v2)

- **D1, approval at delivery (S19b).** An answer is given only if, at delivery, every document its cited evidence rests
  on is:
  - still **approved** (new);
  - still readable by the asker (S13, S16);
  - for a passage, still the version it was read at (S19).

  Otherwise it is refused with today's statuses: 401, 403 or 404 for access, as `/api/ask` gives today, and 409 for the
  evidence. A document deleted mid-answer is not approved.
- **D2, what evidence rests on, fixed when it is built.**
  - **A passage** rests on its document, at the version read (as today: `read_n`, `read_sha`).
  - **A process record** rests on the document its record names (`source_id`).
  - **A fact** rests on the document its object's `source_ref` names when the evidence is built
    (`process_registry:<document>`, `compliance_latest:<document>`). It rests on none when the ref names none.

  Delivery never reads the facts map or the process registry. It reads only the register and the request's visibility,
  so it never waits behind a rebuild (S7).
- **D3, every answer channel.**
  - **The written and avatar channels** deliver through one function, `deliver`, which makes both checks with the
    route's own permissions: `knowledge.ask`, and for the avatar route `avatar.use` as well (S16b).
  - **Tibi's channels** keep their digest check, proven by tests: a withdrawal, a deletion and a restriction each
    change the digest.
  - **Not answer channels, stated:**
    - search (ranked results, which the pages filter as today);
    - receipts (history, REF S18);
    - the diagram route (Bug #2191 takes its leak);
    - the ontology agent's run (an operator's planning tool, whose output is proposals for approval);
    - the unused `/api/sales/source` route (Bug #2192).
- **D4, the avatar route (S16b).** It makes both checks after its rendering call, with today's statuses for the same
  causes as `/api/ask`.
- **D5, one place.** `deliver` holds the checks. A runtime inventory test proves that nothing goes around it: it calls
  every route of the core and of the Sales app with a recording fake answer service, and any route that obtains an
  answer and returns without `deliver` having run fails.
- **D6, nothing else changes.**
  - An answer whose evidence is unchanged is delivered as today, with the same body and the same usage id. The
    recorded `rests_on` is excluded from the response.
  - The readability and version checks are unchanged. The evaluation runners are unchanged.

## Design (v2)

- **`Citation` gains `rests_on: list[str]`,** excluded from the response. It is filled where each citation is built:
  - **passages:** `[source_id]`, in the answer service;
  - **process records:** the record's `source_id`, in the answer service's process fallback;
  - **facts:** parsed from the object's `source_ref` in the ontology router's `_evidence`. The parse is local code
    there, with no import of `answer` or `evidence`, so no package-cycle edge.
- **`EvidenceBundle.recheck`** takes a third check, `approved(item)`. The bundle builder copies each citation's
  `rests_on` onto its item. An item is approved when every document it rests on is approved now.
- **`approved_of(source_id)`** is wired by `create_app` next to `version_of`. It reads the register: approved if the
  record exists and its approval is `approved`. If the read itself fails, the item counts as not approved (fail
  closed: 409).
- **`assistant/api/delivery.py`** holds `deliver(request, answer_service, question, result, permissions)`:
  1. `still_allowed` for each permission (S16);
  2. the bundle;
  3. `recheck(may_read, version_of, approved)`.

  `/api/ask` calls it with `("knowledge.ask",)`. `/api/avatar/answer` calls it, after rendering, with
  `("avatar.use", "knowledge.ask")`.
- **The inventory:** `deliver` notes on the request that it ran. The test's fake answer service notes that an answer
  was obtained. The test calls every route of both apps and fails a route whose request obtained an answer with no
  delivery noted.

## The failure list

- **The evidence changing underneath,** through each channel and each citation type (passage, process record, fact):
  approval withdrawn, a new version, the document deleted, the document restricted. Each is a named test, done during
  generation through a fake generator's hook. The withdrawal's own rebuild of the facts map runs before delivery in
  the test, as it does in production.
- **Access changing mid-way:** a session revoked, a role removed, `avatar.use` lost, during generation or rendering. The
  status is as `/api/ask`'s.
- **Two requests at once:** an ask runs while a withdrawal commits. Delivery reads the register without waiting (S7).
- **A dependency down or slow:** the avatar's rendering failing or slow. The checks run after it.
- **A crash, a restart, duplicate input:** delivery writes nothing. The usage entry is today's.
- **A write that fails:** none. **Date and time, model output:** not involved; the generator is faked.

## Tests

- **Named tests, per channel and per citation type:**
  - each failure line above;
  - **the other direction, D6:** an answer whose own evidence is unchanged is given with the same body, while another
    document is withdrawn at the same moment;
  - the process-record fallback, for a reader with a restricted document.
- **The runtime inventory test (D5).**
- **Tibi:** the digest changes on a withdrawal, a deletion and a restriction.
- **A seeded random-scenario suite.** It mixes withdrawals, new versions, deletions, restrictions and revocations at
  random points, over both channels and all three citation types. It checks that nothing withdrawn, deleted, changed or
  unreadable is given, and that unchanged evidence is given.
- **Guards:**
  - the approval check;
  - the deletion closing;
  - the avatar route's delivery;
  - `rests_on` filled for facts.
- **Restated with the change, and recorded:**
  - H3b's round-3 test that asserts a withdrawn source's answer is given, which now inverts;
  - the evidence contract's conformance test, for the three-argument `recheck`.

## Stated limits

- **The check is the last moment, not a lock.** A withdrawal committed after the recheck is not seen by that answer, as
  with S19 today.
- **Shared facts.** A fact shared by several processes rests on the document its record names, which is the last
  process to list it.
- **A fact whose ref names no register document** (an external or compliance source) rests on none and is given as
  today.
- **A withheld answer** is still in the usage log as answered, with a receipt.
- **A failed rebuild.** A facts map left stale by a failed rebuild can give a 409 ("ask again") until it is rebuilt.
- **Uncited full-context evidence** is not rechecked.
- **Tibi's voice** checks the digest before a reply's first sentence only. That is the engine's, and it is frozen.
- **Tibi's records keep pending references by design.** A "cited document" for Tibi is a record's evidence as the
  digest covers it.
