## The independent review (on `8a08a2c`)

**PASS,** with nothing above Low. The report is local: `research_notes/independent-review-2026-10-05-S68.md`.

- **IR1, a follow-up.** If an account is suspended between the recovery command's own check and its transaction, the
  transaction now refuses and writes nothing. That is safer than before, when it wrote a recovery for the suspended
  account. But the command lets the error escape (a traceback, exit 1) instead of printing "No active account with that
  login." and returning 2. The fix (catch `IamError` in `recover`) is a code change, so it waits for a follow-up, since
  code does not change between a PASS and its merge. It is recorded on REF F11 #2170.
- **IR2, stated limit.** `Identity.emergency_recovery` is a public method with no actor and no permission check. It is
  the host's procedure, and the host command is its only caller. Before S68 a route doing these writes would have
  failed ruff's private-member check; now no check limits its callers. A boundary rule that only `assistant.iam.__main__`
  calls it is a follow-up on REF F11 #2170. IR1 itself was fixed in REF S69 #2200; the boundary rule was not.
- **IR3, records.**
  - The parity tests' copies of the old code carry two harmless edits: `command._identity`, and annotations dropped from
    a signature.
  - The gate's "1,579 passed" leaves out the 57 guard proofs, which run separately.
